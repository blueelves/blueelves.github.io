记录一下这个博客从零到上线的完整过程。整体只需要三样东西：Node.js、一个 GitHub 仓库、一套静态站点生成器。

一、为什么选 Hexo

静态博客生成器有很多，选 Hexo 的理由很朴素：

  • 中文文档齐全，社区活跃
  • 生成纯静态 HTML，托管成本为零
  • 写文章就是写 Markdown，不需要数据库

同类还有 Hugo（更快）、Jekyll（GitHub 原生支持），但 Hexo 的插件生态和主题数量对新手最友好。

四、网站地址的两个配置项

这是最容易出错的地方。_config.yml 里的 url 和 root 必须和 GitHub Pages 的实际地址一致，否则 CSS 和 JS 全部 404，页面会变成一堆没有样式的纯文字。

GitHub Pages 有两种站点：

类型 仓库名要求 访问地址
用户主页站 必须叫 <用户名>.github.io https://用户名.github.io/
项目站 其他任意名字 https://用户名.github.io/仓库名/

⚠️ 关键：仓库名必须正好等于 <用户名>.github.io，才会被识别成用户主页站。哪怕只差一个字母（例如用户名是 blueelves，仓库却叫 blueelev.github.io），GitHub 也会把它当成普通项目站，此时地址必须带仓库名后缀，root 也要跟着改成 /仓库名/。

六、部署方式

方式 A：GitHub Actions（推荐）

在仓库里放一个工作流文件 .github/workflows/pages.yml，每次 git push 后 GitHub 自动构建并发布。

需要在仓库 Settings → Pages → Source 里选择 GitHub Actions。

七、常见问题

现象 原因 解决
页面没有样式 root 配错了 检查仓库是用户站还是项目站
404 Pages 的 Source 没选对 设为 GitHub Actions 或 gh-pages 分支
改了主题没变化 浏览器缓存 硬刷新 Ctrl + F5
中文标题乱码 编码问题 确保文件是 UTF-8
Actions 构建失败 缺 lock 文件 本地跑一次 npm install 生成 package-lock.json 并提交

小结

搭博客这件事，最难的不是技术，而是开始写。把架子搭好之后，剩下的事只有一件：持续地写。
