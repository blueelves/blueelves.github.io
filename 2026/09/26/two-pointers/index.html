双指针：从两数之和到三数之和

在一个有序数组里找出两个数，让它们的和等于目标值——这是双指针最经典的入门题。把这题吃透，三数之和、盛最多水的容器、接雨水都能顺着推出来。

一、核心思想

数组有序，这是双指针能用的前提。设左指针 l 指向最小的数，右指针 r 指向最大的数：

每一步都比较 numbers[l] + numbers[r] 和目标值：

比较结果 含义 动作
sum < target 和太小 l++ 换一个更大的数
sum > target 和太大 r-- 换一个更小的数
sum == target 命中 返回

二、为什么这样不会漏解

关键在于单调性：

  • 如果 numbers[l] + numbers[r] < target，因为数组递增，对同一个 l 而言，r 再往左走只会让和更小，永远不可能等于 target。所以 l 这个位置可以彻底排除，只能 l++。
  • 反之，如果和太大，对同一个 r 来说，l 往右走只会让和更大，也不可能命中，所以只能 r--。

每个分支至少排除一个不可能的下标，所以循环最多走 n 步：时间 O(n)，额外空间 O(1)。

三、C++ 实现

几个容易忽略的细节：

  • vector<int>& numbers 的 & 是引用，不加就会把整个数组拷贝一遍
  • {l + 1, r + 1} 是列表初始化，直接在原地构造 vector；写成 (l + 1, r + 1) 就变成逗号表达式了，只返回最后一个值
  • return {} 不是为了逻辑，而是为了让所有分支都有返回值，否则属于未定义行为

四、我踩过的三个坑

坑 1：变量名和身份对不上

程序能跑，但读的人（包括三天后的自己）会完全懵：为什么 sum 能当数组下标？

修法：左指针就叫 left，右指针就叫 right，和就叫 sum。

坑 2：while 条件让循环一次都不执行

这是把输入值和指针用了同一个变量。结果是程序对所有合数都输出”是质数”——因为压根没检查。

坑 3：三数之和里三个分支全不成立 → 死循环

if 里比较的是 num + n[right]，else if 里比较的却是 num + right（下标而不是数组元素）。两个量叉开了 1，就制造出一个”三个条件都不满足”的空隙——循环体什么都不做，指针不动，死循环。

教训：==、<、> 本来应该穷尽所有可能。最后一个分支直接写 else，就从语法上杜绝了这类空隙。

三点必须注意：

  1. 每换一个 i，l 和 r 都要重置
  2. 命中后必须移动指针，不然原地打转
  3. 数组必须先排序，双指针依赖有序

六、复杂度对比

题目 暴力 双指针 额外空间
两数之和（有序） O(n²) O(n) O(1)
三数之和 O(n³) O(n²) O(1)
四数之和 O(n⁴) O(n³) O(1)

小结

记住这几句话就够了：

  • 和偏小 → 左指针右移；和偏大 → 右指针左移
  • 前提是数组有序
  • 多轮双指针，每轮都要重置指针
  • 命中后一定要移动指针
  • 条件如果本应穷尽，最后一个分支就写 else
